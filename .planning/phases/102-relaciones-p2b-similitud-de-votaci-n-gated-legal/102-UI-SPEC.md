# Phase 102 — UI Design Contract

> Visual and interaction contract for RELACIONES P2b — Similitud de votación (gated legal). Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **This phase does NOT introduce net-new visual design.** It adds ONE gated 5th axis at the END of the existing `/comparar` route (Phase 101, `app/app/comparar/page.tsx`), inside the exact same régimen-locked token system. The entire contract inherits Phase 101's spacing / typography / color / registry decisions verbatim — this document only specifies the DELTA: the vote-similarity sibling section, its mandatory caveat legend, its degraded states, its flag-gated absence, and the anti-DW-NOMINATE visual prohibitions that are SHARPER here than anywhere else in the product.
>
> **CRITICAL DESIGN INVERSION vs Phase 101:** the four factual axes of Phase 101 use `RelacionesEjeComparar`, whose intersection figure is highlighted in `text-accent-product` (petróleo, a NEUTRAL count highlight). The vote-similarity axis MUST NOT reuse that primitive and MUST NOT highlight its number in petróleo — a colored/emphasized similarity figure would visually encode "agreement level" and cross the anti-DW-NOMINATE line. The N/M/% is rendered as **plain body text**, weight-neutral, with the caveat legend given MORE visual weight (adjacent, unavoidable) than the number itself.

| md | 16px | `mt-4` intersection block top, content vertical rhythm inside the section |
| lg | 24px | `md:gap-6` (only if a two-column A/B echo is used — see layout note; default is single-block, no A/B split for this axis) |

**Exceptions:**
- `scroll-margin-top: 5rem` (80px) applies automatically to any `[id]` anchor (globals.css LOCKED). If the section gets `id="similitud-votacion"`, it inherits this — but a rail chip is NOT added (see Interaction contract: no deep-link chip for the gated axis).

**LOCK — `mt-12` boundary (sharper than Phase 101):** The vote-similarity `<section>` MUST be the LAST sibling under `<CompararEjes>` render output, at `mt-12`, with its OWN heading and its OWN legend. It MUST NOT be nested inside, adjacent-without-mt-12, or visually continuous with the four factual axes. The `mt-12` gap is load-bearing: it is the visual declaration that "how they voted" is a DIFFERENT, legally-gated, caveat-bound category — not the fifth item in a factual list.

## Typography

Inherited `var(--text-*)` scale. Phase 102 uses exactly these roles — 3 sizes, 2 weights. **No `text-[…px]`, no ad-hoc `rem`** (source-scan guard, DEBT-05).

| Role | Token / class | Size | Weight | Line Height | Usage |
|------|---------------|------|--------|-------------|-------|
| Section heading | `text-xl` (`var(--text-xl)`, 20px) | 20px | 600 semibold | ~1.2 (snug) | `<h2>` of the vote-similarity section |
| N/M/% figure + body | `text-sm` (`var(--text-sm)`, 14px) | 14px | **400 regular** | 1.5 | the "Coinciden en N de M votaciones compartidas (X%)" line, the caveat legend, the coverage declaration, the degraded-state text, empty text |
| Micro / fecha | `text-xs` (`var(--text-xs)`, 12px) | 12px | 400 (mono for fecha) | 1.4 | `fecha_captura` / provenance line |

**Weights:** exactly two — `font-normal` (400) and `font-semibold` (600). The section heading is the ONLY `font-semibold` on this surface.

**LOCK — the number is NOT emphasized:** Unlike Phase 101's intersection figure (`font-semibold text-accent-product`), the "N de M (X%)" figure here is rendered in **`text-sm` weight-400, default `--foreground`**, with NO petróleo, NO bold, NO larger size. The number carries the SAME visual weight as the caveat sentence surrounding it. Emphasizing the figure (bold/color/size) would present coincidence as a headline signal — precisely the DW-NOMINATE affordance this phase exists to prevent. If any element in the section is emphasized, it is the caveat, not the number.

## Color

60/30/10 régimen, all via hsl tokens (cero-hex LOCKED). No new color. **The accent budget for this axis is DELIBERATELY EMPTY.**

| Role | Token | Usage |
|------|-------|-------|
| Dominant (60%) | `--background` (crema `40 33% 97%`) / `--foreground` | section surface, ALL text including the N/M/% figure |
| Secondary (30%) | `--muted-foreground` (`222 14% 42%`) | caveat legend, coverage declaration, degraded-state text, provenance/fecha |
| Accent (10%) | `--accent-product` (petróleo `183 38% 26%`) | **NOT USED on the figure.** Permitted ONLY for `focus-visible` outline on any interactive element the section might carry (there are none by default — the axis is read-only text). |
| Destructive | `--destructive` | **not used** — zero destructive actions. |

**Accent reserved for (explicit, closed list for this phase):**
1. `focus-visible` outline (2px `outline-accent-product`) — only if an interactive element exists (default: none).

That is the ENTIRE accent list. In contrast to Phase 101, petróleo does NOT touch the intersection figure here.

**LOCKS (anti-DW-NOMINATE — the core of this phase):**
- **No color encodes coincidence, agreement, affinity, or ideological position.** No red/green "agree/disagree", no gradient, no heatmap, no traffic-light, no warm/cool scale keyed to X%. Not even as an easter egg.
- **No progress bar, gauge, meter, dial, sparkline, or bar-length keyed to X%.** The percentage is displayed as text ("(78%)"), never as a filled bar or radial. A filled bar IS a visual similarity encoding.
- **No petróleo highlight on the figure.** The count is plain foreground text. Petróleo's role in Phase 101 (neutral count highlight of factual intersections) is deliberately withheld here because for VOTE similarity, even a neutral highlight reads as "here is your affinity score".
- Dark mode: no per-phase overrides; inherits Phase 101 token pinning.

- The figure is presented for a SINGLE pair on-demand only. No list, no leaderboard, no "los que más coinciden", no sorting of anything by coincidence.

## Interaction & Layout Contract

### Placement — 5th axis, LAST, separated (VSIM-01)
- Rendered as the **final** sibling `<section className="mt-12">` returned by `CompararEjes` (`app/app/comparar/page.tsx`), AFTER `ejeMilitancia`, `ejeComisiones`, `ejeCoautoria`, `ejeZona`. It is the only axis with its own legend block; the four factual axes carry their group discipline from Phase 101.
- **Own heading + own caveat legend + own coverage declaration**, in that reading order: heading → caveat (mandatory, unavoidable) → figure → coverage → provenance. The caveat precedes or immediately wraps the figure so a reader cannot see the number without the caveat.
- The section does NOT reuse `RelacionesEjeComparar` (petróleo-highlight primitive). A dedicated `components/similitud-votacion-comparar.tsx` presentational component renders the neutral figure + caveat + coverage + provenance. Presentational PURE (server passes resolved values; never touches Supabase, never re-computes).

### Layout — single block, not A/B split
- Vote similarity is a PAIR metric (one number for A↔B), not a per-parlamentario value, so it does NOT use the `md:grid-cols-2` A/B column echo of the factual axes. It is a single full-width block: heading, caveat, figure, coverage, provenance stacked vertically. This structural difference REINFORCES the mt-12 frontier (it visibly is not "another factual axis").

### Gating — deny-by-default, absence is total (VSIM-02)
- Flag read ONLY via `vsimPublicEnabled()` in `app/lib/vsim-gate.ts` (byte-mirror of `money-gate.ts`, `=== "true"`, fail-closed).
- When `vsimPublicEnabled() === false` (PROD default): the vote-similarity section is NOT rendered — `return null` server-side BEFORE any `.rpc("coincidencia_votos_par")` call. No data is fetched, no DOM node exists. This is checked at the top of the render branch, not via CSS `hidden`.
- When flag ON (local/preview only, for the dossier cold-read): the section renders with live data from `coincidencia_votos_par(p_a, p_b)`. The phase delivers DOM evidence of the ON state in preview; PROD stays OFF until the human legal sign-off flips it (out of agent scope).
- **No deep-link rail chip** for this axis. Unlike `#relaciones` on the ficha, the gated vote-similarity section does NOT get a nav chip (it must not exist as a navigable target when gated, and even when ON it is subordinate to the caveat, not a promoted anchor). An `id` for scroll-margin is optional and non-load-bearing.

### Data channel
- NEW RPC `coincidencia_votos_par(p_a, p_b)` (migration `0068`): secdef, `search_path=''`, `statement_timeout '5s'`, drop-before-create, double-revoke CERO grant, allowlisted in `PUBLIC_RPC_ALLOWLIST` (Direction-B, registered in Wave 0 with the migration WRITTEN — lesson 101-02). Returns the AGGREGATE for the pair only: `n_coinciden`, `m_compartidas`, `fecha_captura_max`. NEVER a list of individual votaciones (that would be a per-roll-call surface; deferred).
- Ids validated against `PARLAMENTARIO_ID_RE` before the `.rpc()` call (already the page's discipline). Pair order canonicalized alphabetically (existing `[a,b].sort()`).
- The `%` is computed in the component/server from N and M (round to integer — Discretion: integer `%`, no decimals, to avoid false precision; if M is small the integer already over-states precision, so no decimals). When `M === 0`, the degraded copy renders and NO `%` is computed.

### Loading & absence
- A `Suspense fallback` shape-matched to the block (heading line + caveat + one figure line) is acceptable; anti-CLS. Since the axis is last and gated, a `fallback={null}` is also acceptable (mirrors the four factual axes' independent streaming).
- Absence of shared votes is ALWAYS the declared degraded copy ("sin votaciones compartidas suficientes en las fuentes consultadas al {fecha}"), never silence, never a fabricated 0%.
