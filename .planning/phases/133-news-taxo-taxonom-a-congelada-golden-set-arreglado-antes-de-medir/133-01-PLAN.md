## Idiom de medición de tests — OBLIGATORIO en todo este plan

**`grep -oE 'Tests[^0-9]+[0-9]+ passed'` SIN `NO_COLOR=1` sale rc=1 y no devuelve nada.**
Verificado en el working tree: vitest emite ANSI aunque la salida vaya a un archivo, y el `22` del
reset (`\e[22m`) es dígito — rompe `[^0-9]+`, el `[0-9]+` consume `22` y falta `" passed"`.
Cero matches, siempre. Un plan que use ese grep pelado se detiene antes de escribir una línea.

Idiom correcto, verificado hoy (`Tests  206 passed`, rc=0):

```bash
NO_COLOR=1 <comando de vitest> 2>&1 | tee /tmp/LOG.log
N=$(grep -oE 'Tests[^0-9]+[0-9]+ passed' /tmp/LOG.log | grep -oE '[0-9]+')
echo "N=$N"
test "$N" -gt <UMBRAL LITERAL>
```

**Nunca basta con "la línea existe":** el número se extrae y se compara contra un umbral literal.
El exit code de vitest, solo, jamás es criterio (`passWithNoTests: true` está activo y los args de
`vitest run` son filtros de nombre, no rutas).
