<objective>
Build the EGRESO pattern (NOTIF-03/04): the `@obs/notificaciones` package that drains the notificacion_envio queue, computes per-subscription novedades via an idempotent cursor, sends the daily digest through Resend (fetch, hard-capped at 100/day), redacts email PII from all logs, and the `digest-daily.yml` GH Actions cron (L-V, dispatch-only launch). Document explicitly that EGRESO is NOT the two-stage ingesta pattern.

Purpose: EGRESO is a NEW pattern — the inverse of ingesta. There is no source to respect, no R2 crudo, no rate-limit 2-3s/host; the recipient is Resend, not a gov WAF. The two-stage rule (CLAUDE.md) does NOT apply and the difference MUST be documented (Pattern 3). The cursor makes re-runs idempotent (never double-send); the hard 100/day cap degrades honestly (over-cap users queued); email is PII that never touches logs/CI/R2.
Output: @obs/notificaciones package + tests + digest-daily.yml cron.
</objective>
