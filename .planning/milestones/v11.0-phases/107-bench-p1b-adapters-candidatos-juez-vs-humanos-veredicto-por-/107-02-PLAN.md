<objective>
Build the two measurement machines that turn candidate numbers into a decision — both PURE and fixture-testable, both host-agnostic — AND surface the first-class es-CL signal the hard veto needs:

0. **es-CL sub-metric (ADDITIVE to the 106 extracción scorer):** extend `MetricasExtraccion` with a first-class `negacion{total, correctas, accuracy}` computed over the negation-stratum cases, so the veredicto machine can read a Spanish negation/fidelity signal that is GENUINELY INDEPENDENT of `value.precision`. The frozen golden CASES (`casos.json` + its sha256) are UNCHANGED — only the scorer's OUTPUT type gains a field; every existing 106 extracción test stays green.

1. **VEREDICTO por tarea (BENCH-05):** a pure function that, per task (routing, clasificación, juez, extracción), compares a candidate `Reporte` against the incumbent `Reporte` using an EXPLICIT declared ε per metric, and emits `{task -> approved-model | incumbent-stays | pending-evidence}`. It MUST be able to say "nada aprueba paridad", MUST treat any es-CL negation deficit (via the NEW `negacion.accuracy`) as a HARD VETO that short-circuits BEFORE the aggregate gate, and MUST return `pending-evidence` when a candidate has no live numbers.

2. **Juez vs humanos (BENCH-04):** a bridge that adapts `PhiJudge` (the `JudgeProvider` from Plan 01) into the `JuzgarFn` the 106 juez scorer consumes, so Phi is measured against HUMAN labels (`human_label`) with the self-preference/position/verbosity hooks exercised. The measurement itself is LIVE (needs the Phi endpoint) → env-gated, never CI. CI covers the bridge shape (mock JudgeProvider) + the scoring machine (already green from 106).
</objective>
